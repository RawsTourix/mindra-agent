# v0.1 Core Kernel — tooling landscape, 2026-08

## Статус

**Область:** version-specific engineering research для `v0.1 Core Kernel`  
**Дата:** 2026-08-18  
**Канонический design:** `docs/versions/v0.1/README.md` после принятия  
**Статус:** research evidence, не semantic architecture

Этот pass проверяет актуальность concrete Python/tooling choices для первой software version после `F31 + DU-32`.

---

# 1. Constraints v0.1

`v0.1` должна:

- быть CPU-only и deterministic в reference profile;
- не требовать Cortex, Environment, Memory или ML framework;
- реализовать exact foundation contracts `DU-01 … DU-06`;
- иметь строгую static typing и architecture dependency verification;
- быть удобной для Windows и Linux/Colab-like environments;
- не выбирать tooling, который затруднит последующий PyTorch/neural stack;
- не вводить runtime dependency без отдельной необходимости.

---

# 2. Python

## Candidate: CPython 3.14

Официальный PEP 745 фиксирует Python 3.14 как stable feature release с bugfix lifecycle до 2027 и security fixes примерно до октября 2030.

Источник:

- https://peps.python.org/pep-0745/

Дополнительный аргумент для MINDRA: стандартный модуль `uuid` Python 3.14 содержит `uuid7()` по RFC 9562, что позволяет использовать sortable causal identities без отдельной ULID/UUIDv7 зависимости.

Источник:

- https://docs.python.org/3.14/library/uuid.html

Актуальная PyTorch release compatibility matrix уже включает CPython 3.14 в поддерживаемый диапазон новых releases, поэтому выбор 3.14 не создаёт очевидный blocker для поздних neural milestones.

Источник:

- https://github.com/pytorch/pytorch/blob/main/RELEASE.md

### Решение для version design

Предпочтительно:

```text
CPython 3.14.x
standard GIL build
requires-python = ">=3.14,<3.15"
```

Free-threaded build не нужен `v0.1`: physical parallelism не является частью acceptance gate Core Kernel.

# 3. Project/dependency manager

## Candidate: uv

Официальная документация uv поддерживает:

- `pyproject.toml` как project root;
- project-local `.venv`;
- cross-platform `uv.lock` с exact resolved versions;
- `uv sync`, `uv run`, `uv lock`;
- `--locked`/`--frozen` execution;
- `required-version` для контроля версии самого uv;
- pure-Python native build backend `uv_build`.

Источники:

- https://docs.astral.sh/uv/concepts/projects/layout/
- https://docs.astral.sh/uv/concepts/projects/sync/
- https://docs.astral.sh/uv/reference/settings/
- https://docs.astral.sh/uv/configuration/build-backend/

### Решение для version design

Использовать:

```text
pyproject.toml
uv.lock committed
.python-version
uv_build
src/ layout
```

Dependency mutation идёт через project metadata/lock, а не ad-hoc `pip install` инструкции.

# 4. Runtime dependencies

Core Kernel может быть реализован средствами Python standard library:

- `dataclasses`;
- `typing` / `Protocol`;
- `collections.abc`;
- `enum`;
- `uuid`;
- `hashlib` / `json`;
- `tomllib`;
- `argparse`;
- `logging`.

### Решение

`v0.1` не получает обязательных third-party runtime dependencies.

Это не запрещает dependencies поздних versions.

# 5. Formatting/linting

## Ruff

Ruff предоставляет единые linter и formatter CLI (`ruff check`, `ruff format`).

Источники:

- https://docs.astral.sh/ruff/linter/
- https://docs.astral.sh/ruff/formatter/

### Решение

Использовать Ruff для:

- formatting;
- import sorting/lint;
- базовых correctness/style rules.

Ruff не заменяет type checker или architecture tests.

# 6. Static typing

## mypy strict

Mypy поддерживает `pyproject.toml` configuration и strict mode; его документация рекомендует `mypy --strict` как сильную целевую конфигурацию для полностью typed codebase.

Источники:

- https://mypy.readthedocs.io/en/stable/config_file.html
- https://mypy.readthedocs.io/en/stable/existing_code.html

### Решение

Новый код Core Kernel должен проходить strict mypy без blanket `ignore_missing_imports` и без неаргументированных `type: ignore`.

# 7. Example/property/state-machine testing

## pytest

Pytest остаётся general-purpose runner с fixtures/assert introspection и поддерживает современные maintained Python versions.

Источник:

- https://docs.pytest.org/en/stable/

## Hypothesis

Hypothesis поддерживает property-based testing и `RuleBasedStateMachine`, где генерируются последовательности операций и invariants проверяются после шагов.

Источники:

- https://hypothesis.readthedocs.io/en/latest/
- https://hypothesis.readthedocs.io/en/latest/stateful.html

### Решение

Использовать:

```text
pytest
+
Hypothesis
```

State-machine tests особенно подходят для staged update/commit/stale/private-state transitions.

# 8. Architecture dependency verification

## Import Linter

Import Linter поддерживает machine-checkable layered, forbidden и independence contracts для Python import graph.

Источники:

- https://import-linter.readthedocs.io/en/latest/contract_types/layers/
- https://import-linter.readthedocs.io/en/latest/contract_types/forbidden/

### Решение

Использовать Import Linter в `v0.1` как explicit enforcement `DU-02` package dependency rules.

Это implementation tool, не semantic dependency model MINDRA.

---

# 9. Build backend

`uv_build` официально позиционируется как native pure-Python build backend uv и подходит проектам без extension modules.

Источник:

- https://docs.astral.sh/uv/configuration/build-backend/

### Решение

Для `v0.1` использовать `uv_build`.

Если поздняя version потребует compiled extension/build script, build backend может быть пересмотрен без изменения F31 semantics.

# 10. Не выбранные инструменты

Этот pass **не делает обязательными**:

- Pydantic;
- TensorDict;
- PyTorch;
- NumPy;
- asyncio;
- Ray;
- Hydra;
- dependency-injection framework;
- OpenTelemetry;
- structlog;
- pre-commit;
- Docker;
- конкретный CI provider.

Их отсутствие в `v0.1` является intentional scope control, а не отрицательным решением для всего проекта.

# 11. Итог

Рекомендуемый concrete foundation stack:

```text
CPython 3.14
uv + uv.lock + uv_build
stdlib-only runtime
Ruff
mypy --strict
pytest
Hypothesis
Import Linter
```

Он удовлетворяет `DU-32` C0 profile и оставляет neural/storage/distributed choices поздним versions.
