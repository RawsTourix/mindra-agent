# Концепция проекта MINDRA

## Статус документа

Этот документ фиксирует общее направление, исследовательскую мотивацию и предметную границу проекта `mindra-agent`.

Он намеренно не является технической спецификацией. Точные module contracts, алгоритмы обучения, размеры представлений, библиотеки, version scope и implementation details принадлежат более конкретной canonical design-документации и ADR.

Если ранняя concept-формулировка расходится с более поздним accepted Design/ADR/contract, приоритет имеет более конкретная каноническая документация.

Актуальный фактический статус проекта не фиксируется в этом concept-документе и всегда определяется [`design/current.md`](design/current.md). Таким образом, концепция остаётся долговечной и не требует переписывания при переходе между design- и software-этапами.

---

# 1. Что такое MINDRA

**MINDRA — Modular Internal Dynamics & Reasoning Architecture** — исследовательский проект модульной когнитивной архитектуры для нейросетевых агентов.

Главный интерес проекта — исследовать системы, в которых выбор поведения зависит не только от внешнего observation/task и заранее заданного единственного reward, но также от внутреннего состояния агента и его собственной истории взаимодействия со средой.

К потенциально исследуемым механизмам относятся:

- world modeling;
- self-modeling;
- внутренние drives;
- appraisal;
- salience;
- episodic/working/long-term memory;
- consolidation/replay;
- global-workspace-like integration;
- intrinsic motivation;
- планирование и policy;
- заменяемый языковой/семантический Cortex backend.

Этот перечень задаёт исследовательское направление, а не утверждает окончательный состав первой реализации.

# 2. Основной исследовательский вопрос

Вместо вопроса:

> Как заставить нейросеть говорить так, будто у неё есть эмоции или внутренние желания?

проект ставит более проверяемый вопрос:

> Можно ли построить агента, для которого события имеют функционально измеримую внутреннюю значимость, зависящую от состояния, памяти, ожиданий, целей и собственного опыта, и показать причинное влияние этой значимости на дальнейшее поведение?

Важна именно причинная и экспериментальная проверяемость.

Если система сообщает текстом «это событие важно», но изменение соответствующего внутреннего механизма не влияет на поведение, память или обучение, такой самоотчёт не считается достаточным evidence.

# 3. Functional subjectivity

В MINDRA термин **functional subjectivity** используется как рабочее инженерно-исследовательское понятие.

Он означает, что одна и та же внешняя ситуация может получать разную внутреннюю оценку и приводить к разным решениям в зависимости от собственного состояния и истории конкретного агента.

Conceptually:

```text
одинаковый внешний мир
+
разное внутреннее состояние / память / ожидания
↓
разная оценка значимости
↓
разное поведение
```

Functional subjectivity не означает автоматически phenomenal consciousness, sentience или наличие субъективных переживаний.

---

# 4. Что проект не утверждает

MINDRA не должен позиционироваться как:

- доказательство создания сознания;
- доказательство наличия qualia;
- готовая AGI-система;
- биологически точная симуляция человеческого мозга;
- модель человеческой психики один к один;
- попытка заменить neuroscience упрощённой программной аналогией.

Биологические и психологические механизмы могут использоваться как источники гипотез и архитектурных аналогий, но функциональная реализация должна оцениваться по собственным измеримым свойствам.

---

# 5. Почему модульная архитектура

Главная инженерная идея MINDRA — исследовать не один монолитный model checkpoint, а взаимодействие нескольких явно разделённых механизмов.

Это нужно по трём причинам.

## 5.1 Диагностика

Можно отключать отдельные механизмы и измерять их реальный вклад.

## 5.2 Заменяемость

Можно заменить Cortex, memory backend, world model или другую подсистему без переписывания независимой части архитектуры, если сохранён её контракт.

## 5.3 Исследовательская валидность

Можно проводить ablation, intervention, counterfactual и parameter-matched controls, а не судить о системе только по итоговому текстовому поведению.

---

# 6. Роль Cortex

LLM или другая крупная pretrained-модель в MINDRA рассматривается как **Cortex backend** — один из источников языковых, семантических и абстрактно-рассуждающих возможностей.

Cortex не должен становиться неявным владельцем всей когнитивной архитектуры.

Ключевой concept invariant:

> Cortex is replaceable; MINDRA is not a wrapper around one particular LLM.

Проект должен позволять исследовать систему с различными Cortex backend и, где это возможно, без Cortex или с dummy/no-op реализацией.

Конкретные модели и способы интеграции выбираются в соответствующем version-specific design и не становятся частью этой концепции автоматически.

---

# 7. Обучение как часть системы

MINDRA интересует не только inference architecture, но и разделение различных временных масштабов обучения.

Исследовательское направление включает возможность различать:

- быстро меняющееся runtime/internal state;
- episodic experience;
- replay/consolidation;
- медленно изменяющиеся neural weights;
- отдельную адаптацию Cortex при необходимости.

Точная training architecture определяется canonical design и конкретизируется version-specific решениями.

---

# 8. Внутренняя значимость вместо единственного внешнего reward

Проект исследует системы, где внешняя награда не является единственным источником ценности.

Возможные источники внутренних сигналов могут включать:

- novelty;
- prediction error;
- uncertainty reduction;
- goal progress;
- competence;
- resource/homeostatic state;
- memory relevance;
- controllability;
- другие значения, если они будут обоснованы design и экспериментами.

Это не означает, что все перечисленные переменные должны существовать в первой версии.

---

# 9. Исследовательский характер проекта

MINDRA должен развиваться по схеме:

```text
гипотеза
→ design
→ реализация
→ контролируемый эксперимент
→ evidence
→ решение о сохранении/изменении механизма
```

Отрицательный результат является допустимым и полезным результатом исследования.

Модуль не сохраняется в архитектуре только потому, что его концепция выглядит убедительно.

---

# 10. Роль человека и coding agents

Архитектурные и исследовательские решения принимаются осознанно и фиксируются в repository documentation.

Coding agents используются для реализации, проверки и анализа, но не являются самостоятельным источником канонической архитектуры.

Целевая модель работы:

```text
research/design discussion
→ canonical documentation
→ detailed Codex task
→ implementation
→ tests/experiments
→ independent review
→ evidence-driven design update
```

# 11. Граница ответственности concept-документа

Этот документ намеренно не является владельцем:

- текущего project status;
